# New client/project onboarding template

1. Confirm the exact client/company, project, work-package name, scope, and
   owner. Do not infer ownership from filenames.
2. Inspect existing refs, PRs, files, links, and history before selecting the
   authoritative path or base commit. Preserve existing entry points.
3. Create a distinct package path and an `AGENTS.md` inside it that names the
   responsible project manager, owned scope, authoritative sources, exclusions,
   interfaces, checks, and approval gates.
4. Add one project-register row per work package. Link to authoritative sources;
   do not duplicate dimensions or specifications in management files.
5. Add missing evidence to the clarification register and confirmed routing or
   workflow choices to the decision log.
6. Create one coherent task branch from the verified base. Keep unrelated
   client/package files out of its diff.
7. Classify requirements, site measurements, supplier data, CAD measurements,
   proposals, and unknowns. Never copy another project's technical values.
8. Validate deliverables proportionately, record the checks, and use the five
   defined status states. Approval and manufacture release require explicit
   authority.
9. Update the dashboard and handoff with one next action.
